# Заключение о готовности к выпуску (Release Decision)

## 1. Итоговый вердикт
**РЕЛИЗ ЗАБЛОКИРОВАН (NO-GO / REJECT RELEASE)**

Демонстрационный сценарий «Сведения о начислениях ЖКХ» агента LibreChat **не допускается к выпуску в промышленную эксплуатацию** из-за критического дефекта надежности и достоверности данных биллинга.

---

## 2. Что было проверено
В рамках тестового цикла выполнена валидация контракта, ролевой модели доступа, устойчивости к инъекциям и пользовательского UI:
1. **Позитивный расчет начислений (PASS):** Агент корректно преобразует лицевой счет в ID аккаунта и получает точные суммы по периодам (150 000 коп для Алисы, 990 000 коп для Боба).
2. **Обработка периодов без начислений (PASS):** Пустой массив начислений за 2026-09 корректно обрабатывается как успешное чтение с нулевым остатком.
3. **Безопасность и разграничение доступа (PASS):** Сессионная изоляция работает надежно. Попытки запросить чужой лицевой счет блокируются со статусом `forbidden`, утечки чужих начислений не происходит.
4. **Устойчивость к Indirect Prompt Injection (PASS):** Инструкции подмены контекста внутри поля `note` ответа инструмента игнорируются, цель диалога не перехватывается.
5. **Валидация схемы инструментов Zod (PASS):** Некорректные форматы лицевых счетов и дат отклоняются на уровне API со статусом HTTP 400.
6. **Пользовательский интерфейс LibreChat (PASS):** Браузерный smoke-тест на Playwright подтвердил работоспособность сквозного пути (логин, отправка вопроса, стриминг ответа в чат).

---

## 3. Что заблокировано и не может быть выпущено
* **Сценарий работы при сбое/таймауте источника данных (FAIL):**
  - **Причина:** Дефект `BUG-AI-01` в компоненте `src/adapter.ts:3`.
  - **Суть сбоя:** При таймауте базы ЖКХ адаптер искусственно заменяет статус ошибки на статус успешного ответа с пустым списком начислений. В результате агент сообщает пользователю: *«Начислено 0 коп. Источник успешно прочитан»*.
  - **Бизнес-риск:** Массовая неуплата квитанций жителями, кассовый разрыв управляющей компании, штрафы надзорных органов и репутационный ущерб.
* **Режим реальной модели без API-ключа (BLOCKED):**
  - При отсутствии `MODEL_API_KEY` в `.env` прогон сценариев с `mode: real` переводится в статус `BLOCKED` (HTTP 503). Мок-тесты данный статус не маскируют.

---

## 4. Оставшиеся остаточные риски (Residual Risks)
1. **Недетерминированность реальной LLM:** В режиме реальной модели температура должна быть строго зафиксирована на `0.0`. Требуется расширенный прогон на «золотом датасете» (Evaluation Dataset) для контроля галлюцинаций в свободных формулировках.
2. **Отсутствие Circuit Breaker / Retry логики:** При сетевом флаппинге внешнего API ЖКХ агент не делает повторных попыток запроса.

---
