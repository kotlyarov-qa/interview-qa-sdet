# Отчет об использовании AI Coding Agent (`AI_USAGE.md`)

## 1. Сведения об агенте и конфигурация
* **Инструмент:** Antigravity AI Coding Agent (на базе Google DeepMind LLM).
* **Конфигурация среды:** Windows 10/11, Python 3.11, Pytest 9.1, Playwright 1.61, Node 24.
* **Настроенные навыки (Skills) в репозитории:**
  1. `skills/add-regression-test/SKILL.md` - шаблон и правила добавления детерминированных тестов на контракты инструментов.
  2. `skills/analyze-trace/SKILL.md` - регламент расследования сбоев и сопоставления полей `source` vs `result` в JSONL-трассах.

## 2. Примеры применения Coding Agent

### Пример 1: Автогенерация каркаса API-тестов на Pytest
* **Промпт к агенту:** 
  > *«Изучи `CONTRACT.md` и сформируй набор тестов Pytest для проверки цепочки вызовов `get_account` -> `get_charges`, проверки разграничения прав для Alice и Bob, а также валидации входных параметров Zod»*.
* **Результат агента:** Агент создал тестовый файл `tests/test_agent_api.py` с фикстурами HTTP-клиента и проверкой статус-кодов.

### Пример 2: Локализация учебного дефекта по структурированной трассе
* **Промпт к агенту:** 
  > *«Используй навык `analyze-trace`. Проанализируй логи в `artifacts/runs.jsonl` для запуска в режиме `tool_mode: timeout`. Объясни, почему модель вернула 0 начислений при таймауте»*.
* **Результат агента:** Агент сопоставил поле `source` (`status: timeout`) и поле `result` (`status: ok, data: []`), указав на строку 3 в `src/adapter.ts`, где происходит несанкционированная подмена контракта.

## 3. Что кандидат проверил и исправил самостоятельно (Human-in-the-loop)

### Исправление решения агента: Устранение Strict Mode Violation в Playwright
* **Первоначальное решение агента:** Агент сгенерировал селектор проверки ответа в чате LibreChat:
  ```python
  reply_locator = page.locator("text=150000")
  assert reply_locator.is_visible()
  ```
* **Проблема:** Тест упал с ошибкой `playwright._impl._errors.Error: Locator.is_visible: strict mode violation: locator("text=150000") resolved to 2 elements`. Оказалось, что интерфейс LibreChat рендерит текст ответа дважды: один раз в визуальном теге `<p class="whitespace-pre-wrap">`, а второй раз в скрытом блоке для скринридеров `<div aria-live="polite">`.
* **Самостоятельное исправление кандидатом:** Я уточнил селектор до `page.locator("text=150000").first` и добавил явное ожидание `wait_for(state="visible", timeout=15000)`. Это обеспечило 100% стабильность браузерного smoke-теста.

### Дополнительная ручная верификация:
* Ручной прогон в веб-интерфейсе LibreChat (`http://localhost:3082`) сценариев:
  - Смена профиля на `alice-timeout` и визуальное подтверждение галлюцинации «0 коп.».
  - Попытка доступа к чужому лицевому счету Боба `20002` через сессию Алисы и подтверждение ошибки `forbidden`.
* Проверка изоляции секретов: подтверждено, что `.env` исключен из индекса Git и секретные ключи не попадают в репозиторий.

## 4. Затраченное время и ограничения

### Затраченное время:
* **Развертывание и исследование окружения:** ~1.5 часа (Docker compose, LibreChat, MongoDB, Fastify bridge).
* **Локализация учебного дефекта и анализ JSONL-трасс:** ~1 час (`src/adapter.ts`, `artifacts/runs.jsonl`).
* **Разработка автотестов (Pytest API + Playwright UI):** ~2.5 часа (8 API тестов, контрактные ассерты, фикс strict mode в Playwright).
* **Оформление документации и скиллов агента:** ~1.5 часа (Release Decision, Test Matrix, Bug Report, Skills, AI Usage).
* **Итого затрачено:** ~6.5 часов (полностью укладывается в норматив ТЗ до 10 часов).

### Ограничения решения (Limitations):
1. **Изоляция на моках:** Основной регрессионный тестовый контур использует детерминированные синтетические данные (`mode: mock`), чтобы исключить флаппинг из-за нестабильности сторонних LLM и затраты на платные API-токены.
2. **Гейт реальной модели:** Для запуска с реальной моделью требуется валидный `MODEL_API_KEY`. При его отсутствии тесты переводят реальный запуск в статус `BLOCKED` (HTTP 503), что изолирует мок-прогоны от ложных падений.
3. **Объем UI-проверок:** Браузерный тест на Playwright автоматизирует базовый сквозной сценарий (Smoke), тогда как детальная логика прав и краевые случаи покрыты быстрыми и надежными API-тестами на уровне Fastify-агента.
