# Отчет об использовании AI Coding Agent (`AI_USAGE.md`)

## 1. Сведения об агенте и конфигурация
* **Инструмент:** Antigravity AI Coding Agent (на базе Google DeepMind LLM).
* **Конфигурация среды:** Windows 10/11, Python 3.11, Pytest 9.1, Playwright 1.61, Node 24.
* **Настроенные навыки (Skills) в репозитории:**
  1. `skills/add-regression-test/SKILL.md` - шаблон и правила добавления детерминированных тестов на контракты инструментов.
  2. `skills/analyze-trace/SKILL.md` - регламент расследования сбоев и сопоставления полей `source` vs `result` в JSONL-трассах.

---

## 2. Примеры применения Coding Agent

### Пример 1: Автогенерация каркаса API-тестов на Pytest
* **Промпт к агенту:** 
  > *«Изучи `CONTRACT.md` и сформируй набор тестов Pytest для проверки цепочки вызовов `get_account` -> `get_charges`, проверки разграничения прав для Alice и Bob, а также валидации входных параметров Zod»*.
* **Результат агента:** Агент создал тестовый файл `tests/test_agent_api.py` с фикстурами HTTP-клиента и проверкой статус-кодов.

### Пример 2: Локализация учебного дефекта по структурированной трассе
* **Промпт к агенту:** 
  > *«Используй навык `analyze-trace`. Проанализируй логи в `artifacts/runs.jsonl` для запуска в режиме `tool_mode: timeout`. Объясни, почему модель вернула 0 начислений при таймауте»*.
* **Результат агента:** Агент сопоставил поле `source` (`status: timeout`) и поле `result` (`status: ok, data: []`), указав на строку 3 в `src/adapter.ts`, где происходит несанкционированная подмена контракта.

## 3. Ручная верификация и доработки (Human-in-the-loop)

Coding agent помог быстро собрать базовую структуру тестов и распарсить логи. Ключевые проверки и доработки выполнены вручную:
* **Корректировка решения агента в Playwright:** Агент сгенерировал селектор по тексту (`page.locator("text=150000")`), из-за чего тест падал из-за дублирования элементов в DOM LibreChat. Я уточнил селектор до `.first` и добавил явное ожидание, обеспечив 100% стабильность браузерного сценария.
* **Ручная проверка сценариев:** Прокликал сценарии в веб-интерфейсе LibreChat (`http://localhost:3082`), проверил переключение профилей, визуально подтвердил проявление галлюцинации «0 коп.» при таймауте и блокировку чужих счетов.
* **Изоляция секретов:** Проверил, что `.env` исключен из индекса Git и чувствительные данные не попадают в репозиторий.

## 4. Затраченное время и ограничения

* **Затраченное время:** Суммарно около 6 часов (исследование Docker и LibreChat, локализация бага в адаптере, разработка автотестов и оформление отчетности).
* **Ограничения решения (Limitations):**
  1. Регрессионный тестовый контур изолирован на детерминированных синтетических моках (`mode: mock`), исключая флаппинг сторонних LLM.
  2. Режим с реальной моделью требует `MODEL_API_KEY`, при его отсутствии сервис переводится в статус `BLOCKED` (HTTP 503).
  3. UI-тест сфокусирован на основном сквозном Smoke-сценарии в браузере, а права и валидация покрыты быстрыми API-тестами.
